Executive Summary

This Tier-1 threat assessment was conducted on April 2, 2026 against the CISCO-EN CLI Mapping Agent, an internal Streamlit web application deployed on Railway PaaS. The application provides AI-powered CLI command translation across six network operating systems (Cisco IOS, IOS-XE, NX-OS; Extreme EXOS, VOSS, SLX-OS) and is intended for use by the Extreme Networks SA team during customer engagements.

The assessment identified 18 findings across four severity levels. Three Critical findings require immediate remediation before the application is considered safe for continued operation. Seven High findings must be resolved within two weeks. The application is currently suitable for controlled internal use only by trusted SE team members with the understanding that the identified gaps exist.

🔴 Critical Findings

CRITICAL T-001 Secrets Management 📄 .env — git remote config

Live Credential Exposed in Repository Remote URL

DescriptionA live GitHub Personal Access Token was embedded in the git remote URL as a credential helper shortcut. While the remote URL itself was not committed as a file, git-filter-repo detected it in the repository's packed-refs and remote configuration. The token had broad repository access scope.
EvidenceRemote URL format: https://[REDACTED_TOKEN]@github.com/[org]/[repo].git
NIST 800-53IA-5 (Authenticator Management) · SC-28 (Protection of Information at Rest)
CISA ControlZT Identity Pillar — Credential Management · CIS Control 16 (Application Software Security)
StatusPending — PAT revocation scheduled 2026-04-03 post team debrief
Completed✓ Token removed from all 42 git commits via git-filter-repo (2026-04-02). Force-pushed to GitHub.
Remediation1. Revoke token at github.com/settings/tokens
2. Generate new fine-grained PAT with repo-only scope
3. Store in .env (gitignored) only — never embed in remote URL
4. Add git-secrets or detect-secrets pre-commit hook
Auditor evidenceToken revocation log from GitHub · New PAT scope screenshot · pre-commit hook configuration · git log showing clean remote URL
TimelineTonight / 2026-04-03 morning
CRITICAL T-002 Authentication 📄 src/ui/components/auth.py:87

Plaintext Password Storage and Comparison

DescriptionPasswords stored in the APP_USERS Railway environment variable are compared using direct string equality (==). A _hash() function using SHA-256 exists in the file but is never called. Any party with access to Railway environment variables (team members, Railway support, dashboard screenshots) can read all passwords in cleartext. Additionally, example passwords appeared in source code comments in a public GitHub repository (now redacted).
Evidenceusers[username]["password"] == password at auth.py:87. Docstring example contained literal credentials [REDACTED] — visible in public repo until 2026-04-02.
NIST 800-53IA-5(1) — Password-Based Authentication (stored credentials must be salted and hashed)
CISA ControlCIS Control 5 (Account Management) · CISA ZT Identity Pillar
StatusOpen — plaintext comparison still in code   ✓ Source comments scrubbed from git history 2026-04-02
Remediation1. pip install bcrypt
2. Pre-hash all passwords: bcrypt.hashpw(pw.encode(), bcrypt.gensalt()).decode()
3. Store hashed values in APP_USERS Railway env var
4. Replace == comparison with bcrypt.checkpw()
5. Rotate all three user passwords
Auditor evidenceCode review showing bcrypt implementation · Railway env var screenshot showing $2b$12$... hash format (not plaintext) · Confirm no plaintext passwords in git history via git log -p | grep -i password
Timeline48 hours
CRITICAL T-004 Injection 📄 src/rag/search.py:78-103

SQL Injection via f-String Query Construction

DescriptionThe _semantic_search() function builds SQL queries using Python f-string interpolation. The os_filter parameter is interpolated directly as a column name without server-side allowlist validation. While the Streamlit UI constrains values via a selectbox, Streamlit URL parameters and session state can be manipulated by a determined attacker to inject arbitrary SQL.
Evidenceconditions.append(f"{os_filter} != ''") — column name injected directly.
conditions.append(f"tag = '{tag_filter}'") — string value injected without parameterization.
OWASPOWASP A03:2021 — Injection
NIST 800-53SI-10 — Information Input Validation
StatusOpen
Remediation1. Validate os_filter against OS_COLUMNS allowlist at function entry — raise ValueError if not in list
2. Validate tag_filter against FUNCTIONAL_TAGS allowlist
3. Use SQLAlchemy ORM column objects instead of raw text() with string interpolation
4. Run SAST scan (bandit -r src/) to catch remaining injection points
Auditor evidenceSAST scan output showing zero SQL injection findings · Code review showing parameterized queries · Unit test demonstrating injection attempt is rejected
Timeline48 hours

🟠 High Findings

HIGHT-003Authentication — auth.py

No Brute-Force Protection or Account Lockout

NIST 800-53AC-7 (Unsuccessful Logon Attempts) · AU-2 · SI-4
RemediationTrack failed attempts per username in session state with TTL. Lock after 5 failures for 15 minutes. Log all auth events.
Status / TimelineOpen   1 week
HIGHT-005Injection — pdf_extractor.py

SQL Injection via Dynamic Column Name in PDF Extractor

Evidencetext(f"UPDATE cli_mappings SET {os_col} = :cmd WHERE id = :id") — os_col interpolated as column name.
NIST 800-53SI-10 (Information Input Validation)
RemediationValidate os_col against OS_COLUMNS allowlist at every function entry point that uses it in SQL. Selectbox is not sufficient — server-side validation required.
Status / TimelinePartial (selectbox limits UI, not server)   1 week
HIGHT-006SSRF — web_crawler.py

Server-Side Request Forgery (SSRF) via Unrestricted Web Crawler

DescriptionThe web crawler accepts any URL from authenticated users with no domain allowlist, no SSRF protection, and no block on cloud metadata endpoints (e.g., 169.254.169.254). An authenticated user could use this to probe Railway's internal network or access cloud provider metadata.
OWASPOWASP A10:2021 — Server-Side Request Forgery
NIST 800-53SC-7 (Boundary Protection) · SI-10
Remediation1. Domain allowlist: *.cisco.com, *.extremenetworks.com, documentation.extremenetworks.com
2. Block RFC 1918 (10.x, 172.16-31.x, 192.168.x), 127.x, 169.254.x, ::1
3. Restrict crawler tab to admin/superadmin roles only
Status / TimelineOpen   1 week
HIGHT-007Web Security — .streamlit/config.toml

CORS and XSRF Protection Explicitly Disabled

EvidenceenableCORS = false and enableXsrfProtection = false in .streamlit/config.toml
NIST 800-53SC-23 (Session Authenticity) · SI-3
RemediationRemove both lines or set to true. If cross-origin integration is needed, configure an explicit origin allowlist rather than disabling entirely.
Status / TimelineOpen   48 hours
HIGHT-008Session Management — auth.py

No Session Expiry or Idle Timeout

DescriptionAuthentication state is stored in st.session_state with no expiry. A session persists indefinitely — an unattended authenticated browser can be used by anyone.
NIST 800-53AC-12 (Session Termination) · IA-11 (Re-authentication)
RemediationStore login timestamp in session state. Enforce 30-minute idle timeout and 8-hour absolute timeout. Re-authenticate for sensitive operations.
Status / TimelineOpen   2 weeks
HIGHT-009Access Control — data_ingest.py

No Role-Based Access Control on Data Ingest

DescriptionThe "Add Data" tab (PDF upload, CSV upload, web crawler) has no RBAC check. Any authenticated user — regardless of role — can insert data into the database and invoke the web crawler.
NIST 800-53AC-3 (Access Enforcement) · AC-6 (Least Privilege)
RemediationWrap render_data_ingest() with is_admin() check. Define role matrix: user = query only, admin = query + upload, superadmin = full access.
Status / TimelineOpen   1 week
HIGHT-010Audit Logging — all components

No Security Event Logging or Audit Trail

DescriptionThe application logs operational events but has no security-relevant logging: no login success/failure events, no data modification audit trail, no admin action log. There is no SIEM integration and no log integrity protection.
NIST 800-53AU-2 (Event Logging) · AU-3 · AU-6 · AU-9
CISACIS Control 8 (Audit Log Management)
Remediation1. Log all login attempts (success/failure) with timestamp, username, source IP
2. Log all data modifications (insert/update/delete) with username
3. Ship logs to Railway log drain or external SIEM
4. Implement append-only log integrity
Status / TimelineOpen   2 weeks
