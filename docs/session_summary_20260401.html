Uploaded Cisco and Extreme vendor documentation (EXOS 22.7, VOSS 9.0) into NotebookLM. Generated 9 per-bin command mapping tables and 27 cross-bin thematic rows. Key discovery: NotebookLM can't handle 60K+ command cells — a vector database was needed.

Built full application: RAG pipeline, 13-tab Streamlit UI, SBA E2E lead agent, per-bin guardrails, zero-hallucination policy, data ingest pipeline.

Key principle: NotebookLM docs → prompt layer only (reasoning rules). CLI data → database only. Separation ensures Claude is data-driven AND architecturally aware.

RAG Pipeline

  1. Query → classify_tag() detects functional bin via keyword scoring
  2. Query encoded to 384-dim vector by all-MiniLM-L6-v2
  3. pgvector cosine similarity search → top-K rows (threshold ≥ 0.35)
  4. Rows + system prompt → Claude → formatted response (never invents commands)

SBA E2E Deployment Order

[ONBOARD] → [IF-PHYS] → [L2-SEG] → [FAB-SDN] → [L3-VIRT] → [SEC-ID] → [MGMT-OPS] → [DIAG-LOG]

Zero-Hallucination Policy

By default, Claude only returns commands verified in the database. If asked for a "best guess" the agent responds with a ⚠️ labelled answer and explicitly states it is not lab-verified. The verified_only filter ensures production users never see unverified rows.

Key NX-OS Architecture Insight — DME Model

Why feature commands exist: NX-OS uses a Data Management Engine (DME). Every protocol has its own sub-tree in the DME that is locked by default. The feature command unlocks that sub-tree, enabling CLI, SNMP, NETCONF, and REST access simultaneously. Without it, no configuration path works — not just CLI.

Rosetta Stone Rule (added to system_master.md): NX-OS requires explicit feature activation for the same functional intent that IOS-XE accepts natively. Example: IOS-XE accepts router ospf 1 directly. NX-OS requires feature ospf first.

NX-OS Guestshell (added to bin_sys_info.md)

On-box Linux container (CentOS). Enable: feature guestshell then guestshell enable. Runs Python 3. Has access to NX-OS mgmt VRF. NX-OS exclusive — no IOS-XE equivalent.

3-Tier Search Architecture

TierScopeStatusWhen triggered
Tier 1Bin-scoped pgvector searchLiveEvery query — classify_tag() routes to one of 9 bins
Tier 2Full-DB fallback (all bins)LiveTier 1 returns zero results — catches mis-tagged rows
Tier 3Web crawl + Claude extractionDesigned — Sprint 5Tier 2 also returns nothing — fetches from vendor docs

When Tier 2 is used, Claude is informed in context with a ⚠️ notice: "No results in bin — results from FULL DATABASE fallback. Note the actual bin of each result."

Architecture Principle: Bin = Index, Not Partition

The bin tag ([L2-SEG], [MGMT-OPS] etc.) is a search routing hint — NOT a data partition. The pgvector embedding encodes semantic meaning of functional_intent and finds correct rows regardless of tag. The bin can be wrong; the 6 OS columns are what matters.

Railway Deploy — All Blockers and Fixes

5 blockers encountered and resolved before the app went live. Each is documented below as a permanent reference for future Railway projects.

Blocker 1 — ModuleNotFoundError: No module named 'src'

Cause: Railway's Python environment doesn't include /app in PYTHONPATH by default.

Fix: Added PYTHONPATH=/app as Railway environment variable.

Blocker 2 — Port mismatch ("application failed to respond")

Cause: Railway injects $PORT=8080. Target port was set to 8501 in Railway Networking settings.

Fix: Change Railway Networking target port to 8080.

Blocker 3 — DATABASE_URL = ${{Postgres.DATABASE_URL}} literal string

Cause: Railway canvas connector between PostgreSQL and the app service injects the reference template. Template only resolves if the service name matches exactly. When typed manually, stored as literal text.

Fix: Remove canvas connector arrow. Copy the real postgresql:// URL from PostgreSQL service → Connect tab → paste directly into app service Variables.

Prevention: No canvas connector = no auto-re-injection on redeploy.

Blocker 4 — relation "cli_mappings" does not exist

Cause: Migration runner split SQL on ; which silently broke execution. All exceptions caught as warnings — migration appeared to succeed but tables were never created.

Fix: Complete rewrite of run_migrations() using raw psycopg2 with explicit per-table cursor.execute() calls. Commit: b0680e6

Blocker 5 — IVFFlat index creation failed on empty table

Cause: CREATE INDEX USING ivfflat WITH (lists=100) requires ≥ 100 rows. Empty table = error.

Fix: Moved IVFFlat index creation from connection.py to seed.py — created after rows are inserted.

Self-Healing Schema (commit 886abf8)

app.py now calls init_db() on every startup (idempotent — skips if tables exist). Schema is always guaranteed when the app is running, independent of whether the Railway releaseCommand ran. DB Browser shows a prominent "🌱 Seed Database Now" button when rows = 0.

Seed Is One-Time Only

Embedding generation (all-MiniLM-L6-v2) is slow on first run: ~90MB model download from HuggingFace + CPU inference for 515 rows. Once seeded, data persists in Railway PostgreSQL permanently. The releaseCommand no longer runs the full seed — only a no-op echo.

pg_dump Backup — PENDING

Do this once T1-T8 pass. Never re-run the embedding seed again after this — just restore from dump on any new Railway project.

Steps

  1. Railway → PostgreSQL service → Connect tab → copy the Public URL (not the internal .railway.internal one)
  2. Run locally: 
    pg_dump "<public-postgresql-url>" \
  --no-owner --no-acl -Fc \
  -f railway_backup_20260401.dump
  3. Store the .dump file securely (do NOT commit to GitHub — contains credentials)
  4. To restore on a new Railway project: 
    pg_restore -d "<new-database-url>" \
  --no-owner -Fc railway_backup_20260401.dump

After pg_dump — Rotate PostgreSQL Password

The PostgreSQL password appeared in conversation. After confirming the dump works: Railway → PostgreSQL service → Settings → Regenerate credentials. Update DATABASE_URL in the app service Variables with the new URL.

What is all-MiniLM-L6-v2?

A 384-dimensional sentence embedding model (~90MB) from Microsoft/HuggingFace. Converts CLI intent text into a vector for pgvector similarity search. Runs entirely inside the Railway container — no data leaves Railway during inference. Not Claude. Claude is only called for the final text response formatting.
