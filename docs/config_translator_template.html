⚙️ Config Translator — Input Template Guide

How to prepare a Cisco configuration file for the CISCO → ExtremeXOS translator. Annotated example based on a real campus network deployment.

How the Parser Works

The Config Translator reads your uploaded file in two passes:

  1. Pass 1 — Extraction: Strips all prose/narrative text. Identifies and extracts only Cisco configuration blocks (CLI lines, section headers, comment annotations).
  2. Pass 2 — Translation: Sends each section to Claude, enriched with verified EXOS syntax from the RAG database. Produces a side-by-side Cisco ↔ EXOS blueprint with inline caveats.

✅ You can include plain-English descriptions, section titles, and deployment notes in your file — the parser will read them for context labelling but will not attempt to translate them. See the annotated example below.

⚠ Placeholder values like <YOUR_PASSWORD> will be carried through as-is. Replace them with real values, or leave as placeholders — the translator will flag them in the output.

Parsing Rules

✅ CLI Command — Translated

  • Lines starting with a Cisco keyword: hostname, vlan, interface, ip, no, spanning-tree, switchport, router, ntp, snmp-server, aaa, line, service, logging, etc.
  • Indented sub-commands (2-space or tab indent = sub-mode body)
  • Included verbatim in the translation prompt

🏷 Section Marker — Label Only

  • Lines matching: ! --- or ! === followed by a title
  • Used to name the section in the output blueprint
  • Example: ! --- VLAN DATABASE --- → output section heading "VLAN DATABASE"
  • Plain ! lines (no title) are treated as blank separators

⚠ Prose / Context Text — Context Only

  • Plain English sentences not starting with a Cisco keyword
  • Numbered steps (e.g. "1. Access Layer Switch Configuration")
  • Paragraphs describing the network design intent
  • Used to infer device role (access / distribution / core) and name sections
  • Never sent to the translation engine

— Blank / Delimiter — Ignored

  • Empty lines
  • Lone ! delimiters (no text after)
  • Lines containing only whitespace
  • Used only to detect section boundaries

Template Specification

Follow these rules when preparing your config file. The closer your file matches this format, the more accurate the translation.

Required Format Rules

Section markersUse ! --- SECTION NAME --- before each logical block. The translator uses these as output headings.
Device boundariesSeparate multiple device configs with ! ============ and a hostname line. Each device is translated independently.
IndentationUse 1 space indent for sub-mode commands (interface body, router body, etc.). Deeper nesting (e.g. BGP address-family) use 2 spaces.
PlaceholdersUse <UPPERCASE_NAME> for unfilled values. These are carried through and flagged in the output.
Comments / intentUse ! Your note here (without ---) to annotate intent. These are shown in the output as context notes.
Prose textOptional. Include deployment notes or design context — the parser reads it for device role detection only.

Known Caveats — Cisco → ExtremeXOS 33.x

These differences are automatically noted in the translated output as inline caveat comments.

Cisco FeatureEXOS HandlingCaveat Note in Output
switchport voice vlan <id>No native voice VLAN concept. Use LLDP-MED media policy.# CAVEAT: Configure LLDP-MED policy for IP phone VLAN assignment
spanning-tree portfastenable stpd s0 auto-edge ports <p># Verified: ExtremeXOS 33.x — RSTP edge port
spanning-tree bpduguard enableenable stpd s0 ports bpdu-restrict ports <p># Verified: ExtremeXOS 33.x
Interface sub-mode syntaxFlat verb-noun syntax — no interface sub-mode in EXOS# EXOS is flat — each command references port/vlan by name
ip routingenable ipforwarding required per VLAN# CAVEAT: enable ipforwarding required for each L3 VLAN
ip dhcp poolEXOS DHCP requires configure dhcp-server + enable dhcp-server# CAVEAT: EXOS DHCP server must be explicitly enabled
switchport trunk native vlan <id>EXOS: untagged port membership per VLAN# CAVEAT: Set native VLAN as untagged in EXOS port config
Port numbering (Gi1/0/1)EXOS uses slot:port notation (e.g. 1:1) or simple port number# CAVEAT: Renumber ports per your EXOS hardware slot/port map
enable secretconfigure account admin <password># Verified: ExtremeXOS 33.x
