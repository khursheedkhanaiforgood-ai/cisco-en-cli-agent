Fix: # Verified Lines as Empty Code Blocks

Bug: Lines like # Verified: ExtremeXOS 33.x appeared as empty-looking code blocks in the clean EXOS output.

Root cause: _parse_translated_output() tagged these annotation lines with status="verified". The clean_script property let all status="verified" lines through.

Fix (config_translate_agent.py:157): 
# Before
elif line.status in ("verified", "unverified"):
    clean_lines.append(line.text)

# After — annotation lines like "# Verified: ExtremeXOS 33.x" now dropped
elif line.status in ("verified", "unverified") and not stripped.startswith("#"):
    clean_lines.append(line.text)

Fix: EXOS Topology Showing [unknown]

Bug: The "After (ExtremeXOS 33.x)" topology diagram showed [unknown] (Access / L2) with no VLANs, interfaces, or device details.

Root cause: Code was calling extract_topology(parse_config(result.full_script)) — the Cisco modal parser on EXOS flat syntax. EXOS commands like create vlan DATA tag 10 produce no parsed sections → empty topology.

New function: extract_topology_from_exos()

Added to cisco_config_parser.py. Two-pass algorithm:

  1. Pass 1 — global VLAN map: scan all lines for create vlan NAME tag ID patterns
  2. Pass 2 — per-device blocks: split on configure snmp sysName "hostname", then parse:
    • SVIs: configure vlan NAME ipaddress X/prefix
    • IP forwarding: enable ipforwarding / enable ipforwarding vlan NAME
    • Default route: configure iproute add default X
    • DHCP pools: create dhcp-server pool NAME
    • Access ports: configure vlan NAME add ports P untagged
    • Trunk ports: configure vlan NAME add ports P tagged

Topology Parser Routing Logic

The topology expander in config_translator.py now selects parsers based on the session state OS keys:

# After topology — gated on target OS key
